# 実装フェーズと未決事項

> [設計ドキュメント索引](./README.md)

## 実装フェーズ

企画書 29章のフェーズに、本書の構成を割り当てる。各フェーズの終了条件を明示する。

| # | フェーズ | 主な作業 | 終了条件 |
|---|---|---|---|
| 0 | 基盤整備 | adapter-cloudflare 化、`wrangler.jsonc` 2本、`.dev.vars` 移行、`cf-typegen`、2プロセス起動、CI（[サプライチェーン対策](./16-supply-chain.md): lockfile固定・Action の SHA 固定・secret scanning を最初から入れる）、**Valibot の共有スキーマ雛形と認可ガードテンプレート（10.3）を先に作る**、**better-auth の最小構成（`anonymous` プラグインのみ、セッションCookieの属性含む）を先行導入** | `pnpm dev` で web と realtime が同時に立ち上がり、D1 バインディングが効く。「すぐ遊ぶ」でゲストセッションが発行できる |
| 1 | ルールエンジン | `src/lib/game/` 一式、カード24種、`applyCommand`、`predictView`、射影、決定論CSPRNG、版数レジストリの雛形 | ルールエンジンの単体テストが全通し。ブラウザも Cloudflare も不要で動く |
| 2 | ローカルプロトタイプ | デザイントークン整備（14.2）、対戦画面、CPU戦、Svelte ネイティブ演出の基本セット（14.4） | 1台のブラウザで CPU 戦が最後まで遊べ、`motionLevel` の3段階が機能する |
| 3 | オンライン対戦基盤 | `MatchRoom` / `MatchQueue` / `GuestIssuanceGuard`、WSチケット発行・**DO側hello検証**（3.5・11.2）、WS プロトコル全メッセージへの Valibot 適用、**対戦参加者の認可チェック（10.3のガードをWS版にも適用）**、再接続、`command_log`/`event_log` | 2ブラウザでランダムマッチが成立し、切断 → 再接続で復帰できる。**フェーズ0で導入済みの最小認証がここで実際に使われる**（認証なしに試合参加できないことを確認） |
| 4 | アカウント・デッキ | better-auth のプラグインを本構成へ拡張（admin/2FA/captcha/haveibeenpwned）、アカウント連携の移行処理、D1 スキーマ、図鑑、デッキ編集、履歴、Queue → D1/R2、メール配送の実装 | ゲスト開始 → 本登録昇格（所有物の引き継ぎを含む） → デッキ編集 → 対戦 → 履歴確認が通る |
| 5 | セキュリティ強化 | **新規導入ではなく既存実装の hardening**: レート制限の本番調整、段階的な不正対策（[11.8](./11-security-controls.md)）、Turnstile の全対象への適用、CSP の最終調整、監査ログと[監視・通知](./14-observability.md)の実装、管理画面（Cloudflare Access含む）、[鍵ローテーション運用](./13-secrets-lifecycle.md)、[脅威モデル](./12-threat-model.md)の記入完了、[セキュリティ要求とテストの対応表](./19-testing.md)の空欄解消、ASVS 判定一覧 | 16.2 のセキュリティテストが全通し、脅威モデルの残留リスクがすべて受容記録済み |
| 6 | 公開準備 | 負荷試験、互換性試験、[復元試験](./18-availability.md)、規約・ポリシー、通報窓口、[脆弱性受付窓口と `security.txt`](./20-vuln-disclosure.md)、[インシデント対応手順](./15-incident-response.md)の整備、サービス終了方針の規約反映、ベータ | 企画書32章の品質指標を測定でき、インシデント発生時に手順に沿って対応できる状態 |

フェーズ1と2はサーバ不要で進むため、企画書の「フェーズ2：ローカルプロトタイプ」を最短で回せる。**ルールエンジンが固まる前に DO を作らないこと。** 当初案は認可・入力検証の本格導入をフェーズ5に置いていたが、これは 2章「セキュリティは後付けしない」という原則そのものと矛盾していた。**認証・認可・入力検証の最小実装はフェーズ0〜3に前倒しし、フェーズ5は「初出」ではなく「強化」に限定する。**

| 項目 | 判断時期 | 備考 |

| 収益化方式 | 運営データ取得後 | 外見のみのスキン方針は維持 |
| 対象年齢・レーティング | 公開前 | |

| ベータの公開範囲 | フェーズ6 | |
