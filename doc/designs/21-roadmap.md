# 実装フェーズと未決事項

> [設計ドキュメント索引](./README.md)

## 実装フェーズ

| #   | フェーズ             | 主な作業                                                                          | 終了条件                                                            |
| --- | -------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 0   | 基盤整備             | Cloudflare構成、ローカル起動、CI、Valibot、認可ガード、匿名認証                   | `pnpm dev` で web / realtime が起動し、ゲストセッションを発行できる |
| 1   | ルール詳細確定       | 盤面寸法、固定ゾーン、向き、距離、生成パラメータ、曖昧語を確定                    | [ルールブックの解釈事項](./05-game-rules.md)が0件になる             |
| 2   | ルールエンジン       | 8種のワニ、盤面生成、布陣、行動、捕獲・運搬・救出・捕食、勝敗、版数レジストリ     | ブラウザ・Cloudflareなしで全単体／プロパティテストが通る            |
| 3   | ローカルプロトタイプ | 対戦画面、布陣画面、CPU戦、盤面演出、アクセシビリティ                             | 1台のブラウザでCPU戦を最後まで遊べる                                |
| 4   | オンライン対戦       | MatchRoom / MatchQueue、WS認証、座席認可、同時布陣公開、再接続、Command/Eventログ | 2ブラウザで対戦が成立し、切断復帰と時間切れが正しく動く             |
| 5   | アカウントと履歴     | 本登録、匿名からの移行、戦績、リプレイ、通報、メール配送                          | ゲスト開始→本登録→対戦→履歴・リプレイ確認が通る                     |
| 6   | セキュリティ強化     | レート制限、Turnstile、CSP、監査、監視、管理画面、復元試験                        | セキュリティテストと脅威モデルの受容記録が完了する                  |
| 7   | 公開準備             | 負荷・互換性試験、規約、ポリシー、窓口、ベータ                                    | 品質指標を測定でき、障害・インシデント対応を訓練済み                |

ルールエンジン実装より先に、ルール本文の解釈事項とマップ仕様を確定する。盤面生成器はゲームバランスそのものなので、UIより先に大量 seed の自動検証と人手レビューを行う。
