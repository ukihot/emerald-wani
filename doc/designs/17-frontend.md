# フロントエンド設計

## 1. 画面構成

| 画面           | パス                | 主な役割                           |
| -------------- | ------------------- | ---------------------------------- |
| ランディング   | `/`                 | 「すぐ遊ぶ」、ログイン、ルール説明 |
| 登録／ログイン | `/signup`, `/login` | 本登録と復帰                       |
| ホーム         | `/home`             | 対戦導線、お知らせ、戦績要約       |
| マッチング     | `/play`             | ランダム、フレンド、CPU戦          |
| 対戦           | `/match/[id]`       | 盤面確認、布陣、手番操作、終局     |
| 対戦履歴       | `/history`          | 結果とリプレイ                     |
| 設定           | `/settings`         | 音量、演出軽減、言語               |
| 管理           | `/admin/**`         | 運営専用、MFAとAccess必須          |

デッキ編集、カード一覧、図鑑は設けない。全プレイヤーが同じ8体を使うことを、対戦開始前の説明でも明示する。

## 2. ビジュアル原則

配色はモノクロームを基調に、エメラルドを「自分が現在操作できるもの」に限定して使う。

- 自分の手番、選択中のワニ、合法な移動先・対象、主要CTA、フォーカスリングをエメラルドで示す。
- 相手のワニ、操作不能な要素、木はモノクロームを維持する。
- 沼、通常マス、木、巣は色だけに頼らず、形、模様、アイコンでも区別する。
- 捕虜は運搬役の下に重ねつつ、所有者と種類を常に読めるよう輪郭とラベルを残す。
- コワニは0Pであることを得点アイコンでも明示する。

## 3. 対戦画面

対戦画面は次の情報を同時に把握できる構成とする。

- 盤面の全マス、ゾーン境界、巣、木、沼
- 両者の全ワニと捕虜状態
- 両者の得点、現在手番、残り活力、残り時間、ラウンド
- 選択中ワニが実行できる行動と必要活力
- 直前の行動履歴

盤面はプレイヤーごとに自分の巣が手前になるよう180度回転して表示してよいが、マスIDとゲーム座標はサーバ基準から変えない。

### 操作フロー

1. 自分のワニを選ぶ。
2. 移動、噛みつき、ジャンプ、ワープ、運搬、捕食から可能な行動を表示する。
3. 対象マスまたは対象ワニを選ぶ。
4. 活力2を消費する遠距離噛みつき、通常運搬、捕食は明示確認する。
5. Command を送信し、サーバの Event で確定する。

不正な操作先は選択不能にするが、サーバでも必ず再検証する。ドラッグ＆ドロップは補助手段とし、クリック／タップだけですべて操作できるようにする。

## 4. 布陣フェーズ

- 盤面生成直後に地形と45秒タイマーを表示する。
- 自分の味方ゾーンだけを配置可能として強調する。
- 8体の配置状況と未配置数を常に示す。
- 確定前は自由に置き直せる。
- 確定操作には「以後変更できない」ことを明示する。
- 相手については「未確定／確定済み」だけを表示し、配置内容を受け取らない。
- 両者確定後、短い同時公開演出を行う。演出中も最終配置を読み取れるようにする。

## 5. 状態管理

```ts
type MatchStore = {
	serverView: MatchView;
	pendingAction: PendingAction | null;
	animationHints: AnimationHint[];
	connection: 'connecting' | 'online' | 'reconnecting' | 'offline';
};
```

- ゲーム状態の正は `serverView` だけとする。
- `pendingAction` は送信中表示と二重送信防止にだけ使う。
- `predictView` は移動経路や選択対象の予告に限定する。
- Event 到着時に予告を破棄し、サーバ状態へ置き換える。
- rev の欠落を検出したら操作を止めて自動再同期する。

## 6. 演出

| 事象           | 表現                                               |
| -------------- | -------------------------------------------------- |
| 通常移動・運搬 | マス間を短い `Tween` で移動                        |
| ジャンプ       | 障害物の上を弧状に越える `Spring`                  |
| 沼ワープ       | 出発沼で縮小し、到着沼で復帰                       |
| 通常捕獲       | 攻撃側が対象マスへ移動し、捕虜を下へ重ねる         |
| 遠距離捕獲     | ビヨーンワニは固定し、対象だけを捕虜表示へ移す     |
| 救出           | 運搬役の捕獲と味方の復帰を同じ EventBatch で見せる |
| 捕食           | 捕虜を消し、得点を更新。終局判定を続けて表示       |

演出は入力を必要以上にブロックせず、`prefers-reduced-motion` と設定値 `motionLevel`（`full`, `reduced`, `none`）へ対応する。

## 7. レスポンシブとアクセシビリティ

- モバイル縦持ちでは盤面全体を画面幅へ収め、拡大表示とパンを補助として提供する。
- PCでは盤面横に行動、履歴、タイマーを配置する。
- すべてのタップ対象を44×44 CSS px以上にする。
- キーボードだけでワニ選択、マス移動、行動選択、確定、ターン終了を行えるようにする。
- 各マスには座標、地形、占有ワニ、捕虜、選択可否を含むアクセシブル名を与える。
- 色覚に依存しない模様とアイコンを使い、テキストのコントラストは WCAG AA を満たす。
- 得点、活力、残り時間は `font-variant-numeric: tabular-nums` を使う。

## 8. アセットと性能

- 8種のワニは盤面用と詳細表示用の2解像度を用意する。
- 画像は WebP / AVIF を基本とし、初回表示に不要な音声・画像は遅延読み込みする。
- ルールエンジンとワニ定義は対戦画面で動的 import する。
- 差分 Event で更新し、完全スナップショットは接続・再同期時に限定する。
- 大きな盤面でもレイアウトシフトを起こさないよう、マス寸法とアスペクト比を先に確保する。
