### 14.2 ビジュアルデザイン方針（D-22）

#### 14.2.1 基本原則

**モノクローム（白・黒・グレースケール）を基調とし、エメラルドを唯一のアクセントカラーとする。** 画面のおよそ7割がモノクロで構成されることを許容し、主役・重要コンポーネントの一部にのみアクセントを差す。

この方針は装飾上の好みにとどまらず、**機能的な意味を持たせる**ことで企画書 12.1「ゲームの状態を一目で理解できる」に直結させる。

> **エメラルド ＝ 「自分が操作できるもの」**

- 自分の手番、自分のカード、選択中の対象、有効な操作先は**エメラルドを帯びる**。
- 相手側の要素・操作不能な要素は**常にモノクロ**のままである。
- したがってプレイヤーは色の意味を1つだけ覚えればよく、盤面のどこに触れるかが一瞬で分かる。

沼・夜・水面という世界観とも整合するため、**既定はダークテーマ**とし、ライトテーマも同一トークンの反転として提供する。

#### 14.2.2 カラートークン

Tailwind CSS 4 の CSS-first 設定（`@theme`）で定義し、CSS 変数として Scoped CSS からも参照できるようにする。

```css
/* src/routes/layout.css */
@theme {
  /* ニュートラル（わずかに寒色へ振ったグレースケール） */
  --color-ink-950: #0a0b0b;   /* 最暗・背景 */
  --color-ink-900: #131515;
  --color-ink-800: #1e2020;
  --color-ink-700: #2e3131;
  --color-ink-600: #4a4e4e;
  --color-ink-500: #6e7373;   /* 中間・境界 */
  --color-ink-400: #969b9b;
  --color-ink-300: #bfc3c3;
  --color-ink-200: #dcdede;
  --color-ink-100: #eff0f0;
  --color-ink-50:  #f8f9f9;

  /* アクセント：エメラルド（単一色相・3段のみ） */
  --color-emerald-400: #34d9a0;  /* 発光・ハイライト */
  --color-emerald-500: #10b981;  /* 主アクセント */
  --color-emerald-600: #059669;  /* 押下・境界 */

  /* UI アラート専用（盤面には出さない・彩度を抑えた1色のみ） */
  --color-danger: #c2453c;
}
```

**色を増やさないための規律**

- アクセントは **エメラルド1色相・3段のみ**。青・黄・紫などを追加しない。
- `--color-danger` は**フォーム検証エラーと運営管理画面のアラートに限定**し、対戦盤面では一切使わない。
- ダメージ・破壊は色ではなく **白の閃光・黒の残像・明度の落ち込み・振動** で表現する（企画書 7.2「過度に残酷な表現は避ける」とも整合する）。

#### 14.2.3 アクセントの使用ルール

| 区分 | 内容 |
|---|---|
| 面積 | 1画面あたりエメラルドの塗り面積は概ね **5% 以内**。線・縁・小面積・グロウに限る |
| 使ってよい | 主要CTA（1画面に1つ）／自分の手番インジケータ／選択中カードの外周／有効な対象のハイライト／活力ゲージ／自分が支配するレーンの表示／フォーカスリング |
| 使ってはいけない | 本文テキスト／大面積の背景・塗り／装飾のためだけの使用／複数CTAの同時強調／相手側の要素 |
| 濃度 | 発光表現は `--color-emerald-400` にごく低い不透明度のグロウを重ねる。ベタ塗りは `--color-emerald-500` のみ |

#### 14.2.4 モノクロ基調での識別性

色数を絞る以上、**明度・形状・パターン・アイコン**で情報を分ける必要がある。これは企画書 12.3「色だけに依存しない状態表現」と同じ方向であり、本方針はアクセシビリティ上むしろ有利に働く。

| 区別したいもの | 手段 |
|---|---|
| カード種別 | **枠のシルエット**。ワニ＝角丸長方形／行動＝上下を斜めにカット／環境＝六角／縄張り＝台形 |
| 種族・生息地 | アイコン＋ハッチング（斜線・点描・波線）パターン |
| レアリティ | コモン＝マット／レア＝ヘアラインの銀縁／エピック＝白金の箔＋高明度の光沢アニメーション（**エメラルドは使わない**。エメラルド＝「自分が操作できるもの」の意味と衝突しないよう、レアリティは形状・光沢・明度のみで表現する） |
| 自陣・敵陣 | 明度差。自陣は明るい面（`ink-800`）、敵陣は沈んだ面（`ink-950`） |
| 状態異常（潜水・日光浴等） | アイコンバッジ＋質感（半透明・水面ノイズ）。色は使わない |
| 攻撃可能 | エメラルドの外周＋アイコン（色のみに依存しない） |

コントラスト比は本文 4.5:1 以上、大きな文字・アイコンは 3:1 以上を満たす。エメラルド上に文字を置く場合は `ink-950` を用いる。

#### 14.2.5 タイポグラフィ

- 和文は system-ui スタック（`system-ui, "Hiragino Sans", "Noto Sans JP", sans-serif`）。Web フォントの追加読み込みは初回表示を優先して MVP では行わない。
- **数値（HP・コスト・攻撃力・活力）は `font-variant-numeric: tabular-nums` を必須**とする。値が変動しても桁位置がぶれず、カウントアップ演出が破綻しない。
- カード名は字間をわずかに詰め、小画面でも1行に収まる字数上限を設ける。
- 階層は 5 段（`display / title / body / label / caption`）に固定し、それ以上増やさない。

### 14.3 対戦画面の状態管理

```
WSClient（src/lib/client/ws.ts）
  ├─ 接続・再接続（指数バックオフ、上限30秒、最大10回）
  ├─ チケット再取得
  ├─ 受信イベントキュー
  └─ 送信キュー（actionId 採番・未 actionResult の再送）
        ↓
MatchStore（Svelte 5 runes / $state）
  ├─ serverView     … サーバから届いた確定状態（唯一の正。8.3のMatchView）
  ├─ predictedHints … predictView（8.5）が返す見た目の予告（ダメージ等の判断は含まない）
  └─ animationQueue … イベントを演出単位に分解したキュー
        ↓
UI コンポーネント（描画は常に serverView + predictedHints + 再生中の演出）
```

**訂正（P0-5）**: 当初案は「クライアントにも `applyCommand` を同梱してローカル暫定状態 (`optimistic`) を計算する」としていたが、`applyCommand` は相手の手札やデッキ順を含む完全な `MatchState` を要求するため、射影済み `MatchView` しか持たないクライアントでは実行できない。`optimistic` という「もう1つの状態」は持たず、`serverView` と、8.5 の `predictView` が返す**見た目だけの予告ヒント**の2つに整理した。

- **演出待ちと通信待ちを明確に区別する**（企画書 12.1）。通信待ちは専用のインジケータを出し、演出中は操作をブロックするがゲーム状態は常に読み取れるようにする。
- 未応答（`actionResult` 未受信）の行動は最大10秒で諦め、`resync` する。
- 演出はスキップ可能。`motionLevel`（14.4.4）を尊重する。

### 14.4 アニメーション設計（Svelte ネイティブ）（D-23）

演出は **Svelte 5 が標準で持つ機能を主軸**に構築する。アニメーションライブラリを別途導入しない。以下は本プロジェクトで使用している Svelte **5.57.0** で利用可能な API を確認したうえでの割り当てである。

#### 14.4.1 使用する API

| モジュール | 使うもの |
|---|---|
| `svelte/transition` | `fade` `fly` `slide` `scale` `blur` `draw` `crossfade` |
| `svelte/animate` | `flip` |
| `svelte/motion` | `Tween` クラス、`Spring` クラス（`Spring.of()` / `Tween.of()`）、`prefersReducedMotion` |
| `svelte/easing` | `cubicOut` `backOut` `backIn` `elasticOut` `bounceOut` ほか |
| テンプレート構文 | `{#key}` による再生トリガ、`transition:` の `\|global` 修飾、`onintroend` / `onoutroend` |

`svelte/motion` の `Tween` / `Spring` は Svelte 5 のクラス API（`spring()` / `tweened()` ストアは非推奨）。`prefersReducedMotion` は**リアクティブな `MediaQuery`** であり、`prefersReducedMotion.current` を読むだけで OS 設定の変更に追従する。

#### 14.4.2 演出とAPIの割り当て

| 演出（企画書 12.2） | 実装 |
|---|---|
| 山札から手札へのドロー | `crossfade` の `send`/`receive`（山札キー → 手札キー） |
| 手札の扇形配置 | `Spring.of()` で角度・座標を追従。動的座標のため Scoped CSS ＋ インラインスタイル |
| 手札の増減・並び替え | keyed `{#each}` ＋ `animate:flip`（`easing: cubicOut`） |
| カード選択時の浮き上がり | `Spring`（`stiffness` 0.15 / `damping` 0.6）でポインタに追従 |
| カード使用時の拡大 | `scale`（`start: 1, opacity: 1`）＋ `backOut` |
| 場への着地 | `crossfade`（手札キー → 盤面スロットキー）＋ 着地時の `Spring` バウンド |
| 攻撃対象への突進 | `Tween` で往復座標を駆動（往路 `backIn` / 復路 `cubicOut`） |
| 噛みつき時の画面振動 | `Tween` の値を Scoped CSS の `@keyframes` に流す（振幅を `motionLevel` で調整） |
| ダメージ表示 | `fly`（`y: -24`）＋ `fade` の out。数値は `Tween` でカウント |
| 潜水時の水面演出 | **カスタムトランジション**（`css` を返す形式） |
| 破壊時の退場 | `scale` ＋ `blur` の out を合成したカスタムトランジション |
| 縄張り・環境の切替 | `{#key territoryId}` ＋ `crossfade` |
| レアカードの光沢 | CSS `@keyframes`（無限ループはトランジションに適さないため） |
| ターン切替の帯 | `{#key turnNo}` ＋ `fly`（`\|global`） |
| 活力ゲージ | `Tween`（`cubicOut` / 250ms） |
| リーダーHP | 減少は `Tween`、被弾の揺れは `Spring`（`preserveMomentum` で連撃を自然に繋ぐ） |
| 勝利・敗北演出 | `draw`（SVGパスの描画）＋ `fade` |
| 画面遷移 | SvelteKit の `onNavigate` ＋ View Transitions API。非対応ブラウザは `fade` にフォールバック |

#### 14.4.3 実装規約

1. **カスタムトランジションは `css` を返す形式で書く。** `tick` は DOM を直接触る必要がある場合の最後の手段とする。`css` 形式は Web Animations API で実行されメインスレッドをブロックしにくく、対戦画面のように多数のカードが同時に動く場面で効果が大きい。
2. **`{#each}` の `animate:flip` には安定したキー（`cardInstanceId`）を必ず与える。** 配列インデックスをキーにしない。
3. `transition:` は既定でローカルに動く。親要素の出入りに連動させたいものだけ `|global` を明示する。
4. `Spring` / `Tween` は **コンポーネント初期化時（effect root 内）に生成**する。派生値には `Spring.of(() => value)` / `Tween.of(() => value)` を使う。
5. **演出の完了待ちを固定タイマーで行わない。** `onintroend` / `onoutroend`、あるいは `Tween.set()` / `Spring.set()` が返す `Promise` で待ち、14.3 の `animationQueue` の進行に接続する。通信遅延と演出時間が混ざると企画書 12.1「通信待ちと演出待ちの区別」が破綻する。
6. Svelte のトランジションを **100要素以上へ同時適用しない**。大量パーティクル（水しぶき、増水）は Canvas に逃がす。
7. `will-change` は演出中のみ付与し、終了後に外す（モバイルのメモリ対策）。
8. 演出中もゲーム状態は常に読み取れる状態を保つ。演出はオーバーレイであり、盤面の情報を隠さない。

#### 14.4.4 演出レベル（motionLevel）

`prefersReducedMotion.current` とユーザ設定を OR で結合した **単一の派生値 `motionLevel` を判断点とする**。個々のコンポーネントが個別に OS 設定を見に行くことを禁止する。

```ts
// src/lib/client/motion.svelte.ts
import { prefersReducedMotion } from 'svelte/motion';

export const motion = {
  get level(): 'full' | 'reduced' | 'none' {
    if (settings.effects === 'off') return 'none';
    if (prefersReducedMotion.current || settings.effects === 'fast') return 'reduced';
    return 'full';
  },
  /** 各演出はこの係数を duration に掛けるだけでよい */
  get scale() { return { full: 1, reduced: 0.5, none: 0 }[this.level]; }
};
```

| level | 挙動 |
|---|---|
| `full` | 全演出。パーティクル、振動、グロウを含む |
| `reduced` | 位置移動と不透明度のみ。blur・振動・パーティクルを止め、duration を 1/2 |
| `none` | 状態変化を即時反映。80ms の `fade` のみ残す |

低性能端末ではフレーム落ちを検出して自動的に `reduced` へ落とす（企画書 26「スマートフォンでは演出負荷を自動調整する」）。

### 14.5 Tailwind と Scoped CSS の分担（企画書 27）

| Tailwind を使う | Scoped CSS を使う |
|---|---|
| レイアウト、グリッド、余白、サイズ | 手札の扇形配置（`transform: rotate()` の動的計算） |
| 14.2 のトークンによる配色・タイポグラフィ | カードの3D反転、白金箔の光沢、レアリティ演出 |
| レスポンシブ（`sm:` `md:` `lg:`） | 攻撃・噛みつき・破壊の `@keyframes` |
| ボタン、フォーム、`hover:` `focus:` `disabled:` | 動的座標を伴う移動（ドロー、着地、突進） |
| フォーカスリング等のアクセシビリティ | カード種別ごとの枠シルエット、ハッチングパターン |

- 配色は必ず 14.2.2 のトークン経由で指定する。コンポーネント内に生の16進カラーを書かない（アクセント面積の統制が効かなくなるため）。
- Svelte のトランジション／`Spring`／`Tween` で表現できるものは、`@keyframes` を手書きせず Svelte 側に寄せる（14.4）。`@keyframes` は無限ループの装飾（光沢など）と画面振動に限定する。
- 大量のパーティクル（水しぶき、増水）は Canvas に逃がす。低性能端末ではフレーム落ちを検出して `motionLevel` を `reduced` に自動フォールバックする（14.4.4）。

### 14.6 レスポンシブ

- **モバイル優先** で設計する。縦持ちを基準とし、3レーンを横に並べたまま縮小する（レーンが盤面の骨格なので折り返さない）。
- タップ対象は最小 44×44 px を確保する。
- 手札はモバイルでは扇形を浅くし、選択時に大きくプレビューする。
- 誤操作防止のため、攻撃・カード使用は「選択 → 対象指定 → 確定」の2段階とする。ドラッグ&ドロップは補助手段に留める。

### 14.7 アクセシビリティ

- 状態を色だけで表さない（潜水＝アイコン＋半透明、攻撃可能＝枠＋アイコン）。モノクローム基調（14.2）はこの要件と同じ方向を向いており、形状・明度・パターンによる区別が既定の手段になる。
- コントラスト比は本文 4.5:1 以上、大きな文字・アイコンは 3:1 以上。
- **エメラルドの意味（＝自分が操作できるもの）を、色以外でも冗長に示す。** 色覚特性によりエメラルドとグレーの差が弱く見える場合に備え、同じ情報を必ず枠線の太さ・アイコン・ラベルのいずれかで併記する。
- キーボード操作は段階的に対応（MVP はデッキ編集と主要導線、対戦画面はフェーズ6）。フォーカスリングはエメラルドで、かつ 3px 以上の実線として色以外でも判別できるようにする。
- `prefers-reduced-motion` は `svelte/motion` の `prefersReducedMotion` で取得し、ユーザ設定と統合した `motionLevel`（14.4.4）を唯一の判断点とする。
- BGM と効果音の音量を個別に調整可能にする。

### 14.8 パフォーマンス

- カード画像は WebP / AVIF、必要解像度の2段階（一覧用・詳細用）を R2 に置く。
- 初回表示に不要な画像・音声は遅延読み込みする。
- 対戦画面は差分イベント配信のみで動かし、完全スナップショットは初回と再同期時に限定する。
- ルールエンジンとカードデータはクライアントで動的 import し、対戦・デッキ編集以外の画面のバンドルには含めない。
