# テスト方針

> [設計ドキュメント索引](./README.md) / [ルールブック](./05-game-rules.md)

## 1. テスト層

| レイヤ         | ツール               | 対象                                                            |
| -------------- | -------------------- | --------------------------------------------------------------- |
| ルールエンジン | Vitest               | 8種の移動・噛みつき、地形、活力、捕獲、運搬、救出、捕食、勝敗   |
| 盤面生成       | Vitest（大量seed）   | 決定性、180度対称、連結性、経路、公平性制約                     |
| 状態機械       | Vitest               | 布陣、ターン、30ラウンド、同一局面3回、投了、時間切れ           |
| 射影           | Vitest               | 公開前の相手布陣が一切漏れず、公開後は両者の盤面が一致すること  |
| 再現性         | Vitest               | seed、版数、Command 列から同じ最終状態と Event を再現できること |
| DO / Worker    | Workers test runtime | WS認証、冪等性、rev、alarm、再接続、アーカイブ                  |
| コンポーネント | Vitest browser mode  | 盤面、布陣、ワニ、捕虜、活力、合法手表示                        |
| E2E            | Playwright           | ゲスト開始→布陣→対戦→捕食→結果→履歴                             |

## 2. ルールエンジンの必須ケース

### ワニ

- 特記のない特殊ワニの前後左右1マス移動と噛みつき
- ヌシワニの8方向移動と噛みつき
- カツギワニの1活力運搬と1ターン1回制限
- ポチャワニが移動済みの敵から噛まれないこと
- ビヨーンワニの通常／遠距離捕獲、間のマス、木、距離、非移動
- ナナメワニの斜め1～2マス、途中マス、斜め噛みつき
- セッカチワニの最大2マス移動と移動ターンの噛みつき禁止
- トビワニの8方向ジャンプ、障害物1つ、着地点、連続ジャンプ禁止
- コワニの前進と斜め前への噛みつき

### 地形と行動

- 木への進入禁止、長距離移動と遠距離噛みつきの遮断
- 空身の沼退出と沼ワープ、占有された沼へのワープ禁止
- ワープ後に残り活力で沼から退出できること
- 運搬中のワープ・ジャンプ・固有能力・噛みつき禁止
- 沼からの運搬退出が方向自由かつ運搬回数に数えられること
- 通常運搬が巣へ近づく直交1マスだけであること
- 敵のいるマスへ通常移動できないこと

### 捕獲・救出・捕食

- 通常捕獲で攻撃側が対象マスへ移り、相手が捕虜になること
- 運搬役を隣接捕獲したとき、捕虜を重ねず正しい2マスへ分離すること
- ビヨーンワニの遠距離救出で3体が正しい位置・捕虜関係になること
- 救出されたワニが同じターン中に行動できること
- 巣上で捕食前に救出できること
- 特殊ワニの捕食で1P、コワニで0Pになること
- 3P到達直後に終局し、それ以降の Command を拒否すること

### ターンと勝敗

- 通常2活力、先手初手のみ1活力、持ち越しなし
- 活力不足の Command が状態を変更しないこと
- 30ラウンド終了時の得点比較と同点引き分け
- 正規化局面の3回目で引き分け
- 30秒タイムアウト時の自動終了と、3回連続時の敗北
- 自発的な `endTurn` で連続タイムアウト数がリセットされること

## 3. 盤面生成のプロパティ

任意の有効 seed について次を検証する。

- 同一 `seed + MAP_VERSION` はバイト単位で同じ盤面になる。
- 存在マス、地形、巣、ゾーンが180度回転で対応する。
- 全通行可能マスが連結している。
- 両陣営から中央までの条件が等しい。
- 通常経路が2本以上ある。
- 沼を使わず敵陣へ到達できる。
- 巣の直前が一本道ではない。
- 自動配置に必要な空きマスが各味方ゾーンに8個以上ある。

生成器が試行上限へ達する seed も明示的にテストし、無限ループを防ぐ。

## 4. セキュリティとプロトコル

- 未認証の保護APIは401、他人の試合・履歴・リプレイは404。
- `hello` 未送信、無効・期限切れ・再利用チケットを拒否する。
- 相手手番の行動は `E_NOT_YOUR_TURN`。
- 古い rev は `E_STALE_REV`、同じ `actionId` は二重適用しない。
- 不正なマス、所有していないワニ、活力不足をサーバで拒否する。
- 布陣中の全 WS フレームとログに相手の `placements` が含まれない。
- 片方が確定しただけでは配置を公開せず、両者確定後に同じ rev で同時公開する。
- `archive_state = archived` になるまで DO の状態を削除しない。

フェーズ6で追加した検証（`pnpm test:unit` と `pnpm verify:phase6`）:

- 全応答に[11.1](./11-security-controls.md)のヘッダーが付き、CSP の `script-src` が nonce 方式のままで `unsafe-inline` を含まない。
- `/admin/**` の CSP から Turnstile の許可が外れ、`frame-src` が `'none'` になる。
- 管理画面は未認証で 401、一般利用者・ゲストで 404、役割を持っていても **MFA 未設定なら入れない**。
- ゲスト発行は Turnstile → バースト（3/60秒） → 1時間3件の順に止まり、**画面経由と `/api/auth/sign-in/anonymous` の両方**に同じ門が掛かる。
- `security_event` に**生 IP・生 User-Agent が保存されない**（ハッシュは日次で変わり、同じ入力でも翌日は別の値になる）。
- Turnstile の検証は、鍵が無い `development` でだけ素通りし、それ以外は**未設定・到達不能でも拒否**する（フェイルクローズ）。
- WebSocket の Upgrade 要求に IP 単位の粗いレート制限が掛かる。
- 週次エクスポート（D1 → R2）が Cron で走り、[復元試験](../restore-drill.md)の手順で書き戻せる。

## 5. 互換性試験（フェーズ7）

### 5.1 過去版リプレイの互換（自動）

`src/lib/protocol/fixtures/*.ndjson` に、**実運用と同じ形式で保存した過去の対局**を
2件（3P決着・30ラウンド引き分け）置く。`src/lib/protocol/replay-compat.spec.ts` が
それを `dispatchCommand`（MatchRoom が使う本物のディスパッチャ）へ流し直し、
同じ Event 列・同じ最終状態になることを検証する。

落ちたときに取る道は2つだけである。

1. 変更が意図せず互換を壊している → 変更を直す。
2. 意図してルールを変えた → **新しい `RULE_VERSION` を切り**、旧版の reducer を
   版数レジストリへ残す（D-25）。fixture を作り直して通すのは誤り。

### 5.2 ブラウザ互換（手動。公開前に実施）

自動化していない。E2E の実行基盤（`vite preview`）は D1 などのバインディングを持たず、
`wrangler dev` を前提に組み直す必要があるため、ベータ公開後の課題とする
（[負荷試験](../load-test.md) 5節）。公開前は次の組み合わせを手で確認する。

| ブラウザ                      | 確認する画面                           |
| ----------------------------- | -------------------------------------- |
| Chrome / Edge（最新）         | 全画面                                 |
| Firefox（最新）               | 対戦（WS 再接続を含む）、布陣、履歴    |
| Safari（macOS / iOS 最新2版） | 対戦、布陣、Turnstile、Cookie の維持   |
| Android Chrome                | 対戦、布陣（タッチ操作と盤面の可読性） |

## 6. 負荷・耐性試験（フェーズ7）

`pnpm load-test`（[`scripts/load-test.mjs`](../../scripts/load-test.mjs)）で、同時対戦・
再接続集中・大量の無効操作・ログ書き出しを測る。測定値・判定基準・分かったことは
[負荷試験と品質指標](../load-test.md)。

フェーズ7で追加した検証（`pnpm verify:phase7`）:

- 規約・プライバシー・セキュリティポリシー・窓口が配信され、窓口の宛先が載っている。
- どの画面からも規約・窓口へ1クリックで行ける（対局画面にはフッターを出さない）。
- `/.well-known/security.txt` が RFC 9116 の必須項目を持ち、**残り30日を切っていない**。
- 過去版リプレイの fixture が版数付きで存在する。
- ベータ公開中であることが画面に出ている。
- **無効試合（`status='void'`）が戦績から外れる**（対戦→投了→`void` 化→戦績が1件減る）。

## 7. CI

PRごとに型検査、lint、単体・プロパティ・コンポーネントテスト、依存関係監査を行う。main へのマージ後に Worker 統合テスト、夜間に E2E と過去版リプレイ互換テストを行う。公開前には同時対戦、再接続集中、大量の無効操作、盤面生成集中、ログ書き出しを負荷試験する。
