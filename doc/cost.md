# 料金と無料枠（どこまで無料で、超えると何が起きるか）

> [デプロイ手順](./deploy.md) / [プラン制約](./designs/03-tech-stack.md) / [監視](./designs/14-observability.md)
> 出典: Cloudflare 公式の料金ページ（Workers / Durable Objects / D1 / R2 / Queues。2026-09-07 時点）

**結論を3行で。**

1. 本プロジェクトは **Workers 無料プランのまま運用できる**。Queues も2026-02-04から無料プランに入った。
2. 無料枠を超えると、**課金されるのではなく機能が止まる**（D1 は2026-09-01からエラーを返す）。
3. 有料へ移るときの最低額は **$5/月**。したがって設定済みの**$2の予算アラートは発火しない**
   （$5未満の請求が存在しないため）。アラートは $6〜$7 に置き直すほうが「想定より使った」の検知になる。

---

## 1. 無料プランの枠（本プロジェクトが使う分だけ）

| 製品                    | 無料枠                                                                   | 超えたとき                               |
| ----------------------- | ------------------------------------------------------------------------ | ---------------------------------------- |
| Workers（リクエスト）   | 100,000 / 日（静的アセットへのリクエストは無料・無制限）                 | リクエストが失敗する                     |
| Workers（CPU）          | 1回の呼び出しにつき 10 ms                                                | その呼び出しが打ち切られる               |
| Durable Objects（要求） | 100,000 / 日（**WebSocket のメッセージ1通＝1要求**、alarm も1要求）      | 要求が失敗する                           |
| Durable Objects（時間） | 13,000 GB秒 / 日（休止中は課金対象外）                                   | 要求が失敗する                           |
| DO の SQLite            | 読み 5,000,000 行/日、**書き 100,000 行/日**、保存 5 GB                  | 書き込みが失敗する                       |
| D1                      | 読み 5,000,000 行/日、**書き 100,000 行/日**、保存 5 GB                  | **クエリがエラーを返す**（2026-09-01〜） |
| R2                      | 保存 10 GB、Class A（書き）100万/月、Class B（読み）1,000万/月、下り無料 | 操作が失敗する                           |
| Queues                  | 10,000 操作/日、メッセージ保持24時間                                     | 操作が失敗する                           |
| Workers Logs            | 200,000 イベント/日、保持3日                                             | ログが落ちる                             |

**無料枠の上限は「請求の上限」ではなく「動作の上限」である。** 使い切ると
エラーが出て遊べなくなるため、[監視](./designs/14-observability.md)の閾値は
無料枠の80%あたりに置く。

## 2. 本プロジェクトの消費モデル

1対戦（2人・実時間8分・20ラウンド程度）あたりの見積り。実測ではなく設計からの概算で、
**公開後にダッシュボードの実数で置き換えること**。

| 資源               | 1対戦あたり | 内訳                                                                       |
| ------------------ | ----------- | -------------------------------------------------------------------------- |
| Worker リクエスト  | 約80        | SSR のページ、認証、マッチング状況の1秒ポーリング、チケット、履歴          |
| DO 要求            | 約175       | WS メッセージ（hello・布陣・行動・endTurn）約130＋手番 alarm 約40＋内部API |
| DO 実行時間        | 約60 GB秒   | 8分×128 MB。手番待ちで休止できる分は課金されない                           |
| DO SQLite 書き込み | 約600行     | `command_log` / `event_log` / 状態更新 / `setAlarm`（1回=1行）             |
| D1 書き込み        | 約16行      | ゲスト2人の作成、終局後の `match` / `match_player`、`security_event`       |
| R2                 | Class A 1回 | リプレイ1本の書き込み（読みは閲覧時のみ）                                  |
| Queues             | 3操作       | 1メッセージ（書き・読み・削除）                                            |

### 無料枠で何対戦できるか

| 制約                   | 計算          | 1日あたりの上限             |
| ---------------------- | ------------- | --------------------------- |
| **DO SQLite 書き込み** | 100,000 ÷ 600 | **約160対戦** ←最初に当たる |
| DO 実行時間            | 13,000 ÷ 60   | 約210対戦                   |
| DO 要求                | 100,000 ÷ 175 | 約570対戦                   |
| Worker リクエスト      | 100,000 ÷ 80  | 約1,200対戦                 |
| D1 書き込み            | 100,000 ÷ 16  | 約6,000対戦                 |
| Queues                 | 10,000 ÷ 3    | 約3,300対戦                 |

**目安: 1日およそ150対戦（＝300人の対局）までが無料枠。**

「1日1,000アクセス」の規模は、その全員が遊ぶわけでなければ**完全に無料の範囲**である。
例えば1,000ページ閲覧のうち100人が1対戦ずつ遊ぶ場合、使用量は無料枠の
2〜3割にとどまる（静的アセットの配信は無料・無制限）。

### 効きどころ（無料枠を延ばしたい場合）

| 施策                                                      | 効果                                                     |
| --------------------------------------------------------- | -------------------------------------------------------- |
| マッチング状況のポーリング（1秒）を WS / SSE に置き換える | Worker リクエストが対戦あたり数十件減る（D-21 の将来案） |
| `event_log` の保存を必要な種別に絞る                      | **最初に当たる制約**（DO の行書き込み）が直接減る        |
| 終局後の DO 掃除を確実に走らせる                          | DO の保存データ（5 GB）を圧迫しない                      |

## 3. 有料プランへ移ると

| 項目                    | Workers Paid（$5/月〜）                                                  |
| ----------------------- | ------------------------------------------------------------------------ |
| Workers リクエスト      | 1,000万/月 込み、超過 $0.30/百万                                         |
| Workers CPU             | 3,000万 CPUミリ秒/月 込み、超過 $0.02/百万                               |
| DO 要求                 | 100万/月 込み、超過 $0.15/百万                                           |
| DO 実行時間             | 400,000 GB秒/月 込み、超過 $12.50/百万 GB秒                              |
| DO SQLite / D1 書き込み | 5,000万行/月 込み、超過 $1.00/百万行                                     |
| DO SQLite / D1 読み込み | 250億行/月 込み、超過 $0.001/百万行                                      |
| D1 保存                 | 5 GB込み、超過 $0.20/GB月                                                |
| R2                      | 保存 $0.015/GB月、Class A $4.50/百万、Class B $0.36/百万（無料枠は継続） |
| Queues                  | 100万操作/月 込み、超過 $0.40/百万                                       |

**有料移行後に効いてくるのは DO の実行時間**である。1日1,000対戦（＝月30,000対戦）なら
DO 実行時間は 30,000 × 60 = 180万 GB秒。込みの400,000 GB秒を超えた分が
`(1,800,000 − 400,000) ÷ 1,000,000 × $12.50 ≒ $17.5/月` として乗る。
他の資源（要求数・行数）は同じ規模でも込みの範囲に収まる。費用は
**対戦の実時間 × 同時対戦数**にほぼ比例すると考えてよい。

| 規模（1日あたり） | 概算の月額           |
| ----------------- | -------------------- |
| 〜150対戦         | $0（無料プラン）     |
| 300対戦           | $5（基本料のみ）     |
| 1,000対戦         | $5 + 約$18 ≒ **$23** |

Resend（メール配送）は Cloudflare の請求とは別勘定である（無料枠の通数は
Resend の料金ページで確認すること）。送るのは確認メールとパスワード再設定だけなので、
ベータ期間の想定量では最小プランで足りる。

## 4. 予算アラートの設定

- 現在の**$2は発火しない**（有料プランの最低額が$5のため）。
- 推奨: **$7**（基本料$5＋想定外の従量$2）でアラート、**$25** で第2段。
- あわせて、無料プランのうちは**枠の消費**を見る。課金ではなく停止が起きるため、
  請求アラートでは気づけない（[監視](./designs/14-observability.md)）。
  - Workers リクエスト / DO 要求 / D1 の行数は各製品のダッシュボードで日次確認。
  - D1 の枠超過はメールでも通知される（2026-09-01の仕様変更）。

## 5. 注意点

- **無料プランでの停止はサービス障害と同じ**である。ベータ公開の告知（利用規約1条）で
  「予告なく停止しうる」と明示してあるが、枠超過が近づいたら有料へ切り替える判断を先にする。
- 上記の数字は**設計からの見積り**である。公開後に1週間の実測を取り、本書の2節を
  実数へ置き換えること（[負荷試験と品質指標](./load-test.md) 6節の指標と同じ場所で見る）。
