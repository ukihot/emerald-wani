# 障害・インシデント対応訓練の手順と実施記録

> 設計上の根拠: [インシデント対応と証拠保全](./designs/15-incident-response.md) / [可用性](./designs/18-availability.md) 15.5

手順書があることと、手順を実行できることは別である。**四半期ごとに1シナリオ以上を訓練し、
所要時間と発見事項を本書へ残す。** [復元試験](./restore-drill.md)と同じ周期で回す。

## 1. 訓練の型

| 種別       | 内容                                             | 使いどころ                                     |
| ---------- | ------------------------------------------------ | ---------------------------------------------- |
| 机上（TT） | 手順を読み、担当と判断を口頭で確認する           | 本番でしか試せない操作（ロールバック、鍵失効） |
| 実施（EX） | staging またはローカルで**実際にコマンドを流す** | 証拠保全、無効試合化、復元、通知               |

**実施できるものを机上で済ませない。** 手順の不備は、実際に叩いたときにしか出てこない。

## 2. 共通の準備

```bash
pnpm dev                       # ローカルで訓練するとき
npx wrangler tail              # 本番/stg のログを見ながら行う（web）
npx wrangler tail -c workers/realtime/wrangler.jsonc
```

訓練で作った証拠ファイルは、記録を残したら消す（個人情報を手元に残さない）。

## 3. シナリオ

### S-1. 秘匿情報の漏えい疑い（公開前の布陣）— 最優先

保護目的 P-5 の直撃。[脆弱性の受付](./designs/20-vuln-disclosure.md)からの報告を起点に、
インシデント対応（[15](./designs/15-incident-response.md)）へ移る流れを訓練する。

```bash
# 1. 証拠保全（**調査より先**）。期間を絞って security_event を書き出す
npx wrangler d1 execute emerald-wani-db --remote --json \
  --command "SELECT * FROM security_event WHERE ts > <開始epoch_ms> ORDER BY ts" > evidence-events.json

# 2. 該当試合の特定と、リプレイの退避（自動削除より前に別プレフィックスへ）
npx wrangler r2 object get emerald-wani-replays/<replay_key> --file evidence-replay.ndjson.gz
npx wrangler r2 object put emerald-wani-replays/evidence/<matchId>.ndjson.gz --file evidence-replay.ndjson.gz

# 3. 影響範囲の試合を無効試合にする（戦績から除外する）
npx wrangler d1 execute emerald-wani-db --remote \
  --command "UPDATE match SET status = 'void' WHERE id = '<matchId>'"
```

判断すること: 射影バグか WS 配信か。原因が特定できるまで**該当機能を止めるか**。
告知は「影響を受けた対戦の参加者へ、事実確認から1週間以内」。

### S-2. 誤デプロイ（機能不全）

```bash
npx wrangler deployments list
npx wrangler rollback <version-id>                                   # web
npx wrangler rollback <version-id> -c workers/realtime/wrangler.jsonc # realtime
```

**ロールバックも DO を再起動し、進行中の WebSocket を全部切る。** 再接続の集中を
想定して、切り戻し後に接続数とエラー率を見る。判断すること: 切り戻すか、前進修正か
（D1 マイグレーションを伴う変更は前進修正のほうが安全なことがある）。

### S-3. WS チケット署名鍵の漏えい

[鍵ライフサイクル](./designs/13-secrets-lifecycle.md) S-01。**併用期間を置かず即時失効**する。

```bash
npx wrangler secret put WS_TICKET_SECRET_V1                             # 新しい値
npx wrangler secret put WS_TICKET_SECRET_V1 -c workers/realtime/wrangler.jsonc  # 同じ値
```

投入後、既存のチケットは全て無効になり、全員がチケット再取得（=再接続）を要求される。
判断すること: `BETTER_AUTH_SECRET`（S-02）も替えるか＝全セッションを切るか。

### S-4. アーカイブの滞留（Queue 障害・R2 保存失敗）

```bash
# 滞留している試合
npx wrangler d1 execute emerald-wani-db --remote --json \
  --command "SELECT id, ended_at FROM match WHERE replay_key IS NULL AND ended_at IS NOT NULL"

# 毎時 Cron の再照合を手で起こす（ローカル/stg。本番は次の実行を待つか再デプロイ）
curl "http://127.0.0.1:8787/cdn-cgi/handler/scheduled?cron=0+*+*+*+*"
```

恒久的に失敗する試合は「リプレイなし」として記録し、結果（D1）は保持する。

### S-5. アカウント侵害の通報

セッション失効 → パスワード再設定の強制 → `security_event` から侵害後の操作の洗い出し。
停止を行う場合は **`admin_audit` に根拠・判断者・期間・通知を必ず記録**する
（[15.5.1](./designs/15-incident-response.md)）。異議申立ての窓口は
`emerald-wani@jocarium.productions`（件名 `[appeal]`）。

## 4. 判定基準

| 項目           | 基準                                                     |
| -------------- | -------------------------------------------------------- |
| 証拠保全の開始 | 事象確認から**30分以内**にコマンドを流し始められること   |
| 無効試合化     | 対象の特定から10分以内                                   |
| ロールバック   | 判断から10分以内に完了                                   |
| 鍵の即時失効   | 判断から30分以内に両 Worker へ投入完了                   |
| 手順の不備     | 見つかったら**その場で本書を直す**（次回へ持ち越さない） |
